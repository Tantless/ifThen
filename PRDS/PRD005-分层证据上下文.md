## prd-分层证据上下文-完成情况

### 目标

为 `realism-02` 建立显式分层证据合同，并把 realtime branch session 的 memory pack 升级到同一套结构，使系统能区分：

- `cutoff_safe_facts`：角色在 cutoff 时可知的上下文
- `future_evidence_digests`：cutoff 后原时间线的 modeler-only 证据
- `branch_facts`：改写后分支内新生成的事实

### 需求

- `build_context_pack()` 必须输出显式 layered fields，同时保留旧字段兼容现有 prompt 和测试路径。
- `future_evidence_digests` 首版只接 cutoff 后的 `SegmentSummary + Topic/TopicLink`，不引入 `RelationshipSnapshot`。
- 每条 future evidence 必须包含来源、时间范围、证据类型、摘要和 `modeler_only_not_character_known` 使用策略。
- 首版 future evidence 预算固定为最多 3 条，避免上下文无界膨胀。
- realtime branch session 的 `session_memory_pack` 必须显式保存 layered context，同时保留兼容投影。
- 本任务不负责主要 prompt 行为改写；future evidence 的泄漏护栏和回复保守度收口仍留给 `realism-05`。

### 验收标准

- `build_context_pack()` 已输出 `cutoff_safe_facts`、`future_evidence_digests`、`branch_facts`、`evidence_policy`。
- future evidence 可由 cutoff 后 `SegmentSummary + Topic/TopicLink` 装配，并带完整元数据。
- 没有 future evidence 时，context pack 仍可正常构建。
- `BranchSession.session_memory_pack` 已升级为显式 layered 结构，并保留兼容字段。
- 测试已验证 future evidence 不会混入 `related_topic_digests`、`current_segment_history` 等角色可知字段。

### 技术方案

- 新增 `src/if_then_mvp/context_builder.py` 统一 API 和 worker 的 context-pack 装配路径，消除两处重复 retrieval 逻辑。
- 在 `src/if_then_mvp/retrieval.py` 中扩展 layered evidence contract，并保持 legacy keys 不变。
- 在 `src/if_then_mvp/branch_sessions.py` 中把 realtime memory pack 升级为：
  - `layered_context_pack`
  - `compatibility.cutoff_safe_context_pack`
  - `persona_priority`
