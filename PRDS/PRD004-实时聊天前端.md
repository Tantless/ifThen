# PRD004-实时聊天前端

## prd-实时聊天前端-完成情况

### 目标

为真实性路线图 `realism-07` 接入实时分支聊天前端：用户改写历史 `self` 消息后进入 branch session，后续继续发送 `self`，后端串行生成 `other` 回复，前端展示输入等待、typing、拆泡延迟和错误重试状态。

### 需求

- 桌面端必须继续走 IPC-only 架构，renderer 不直接调用 Python HTTP API。
- 新增 branch session service，覆盖创建会话、读取会话、追加消息、创建 reply job 和查询 reply job。
- 改写提交后创建 branch session，并把主聊天窗口切到实时分支视图。
- 分支视图保留原时间线至目标消息，目标消息显示为改写文本，目标之后的原时间线消息不再显示。
- 用户可继续发送多条 `self` 消息，最后一条消息后等待 1.5 到 2 秒 idle window 再创建 reply job。
- reply job queued/running 期间展示可见状态，不并行触发第二个有效 reply job。
- 用户在 reply job 未提交前追加 `self` 消息时，前端进入新一轮 idle window，后端 supersede 旧 job。
- `other` 回复返回后按短句拆成多条气泡，并按短文本约 1 秒、中短句约 2 秒、长句约 3 秒递进展示。
- 失败状态可见，并提供重试入口。
- 原有 `single_reply` / `short_thread` 数据适配和展示能力保留为兼容路径。

### 验收标准

- 用户改写后可以进入实时分支会话。
- 用户连续发送多条消息时，只在 idle window 后触发一次 reply job。
- reply job queued/running 时不会并行触发第二个有效回复任务。
- LLM 未返回前用户追加消息时，旧 job 不会把过期回复展示到当前 UI。
- `other` 回复会按短句逐条出现。
- typing、排队、失败和重试状态可见。
- 原有 short-thread adapter 测试仍通过。

- 已新增 branch session 桌面端类型、`branchSessionService`、Electron backend client 方法、IPC handler 和 preload bridge，保持 renderer 继续通过 IPC-only 架构访问 Python API。
