# PRD003-分支会话后端

## prd-分支会话后端-完成情况

### 目标

为真实性路线图 `realism-06` 建立实时分支会话后端最小闭环：用户在改写历史消息后继续扮演 `self`，LLM 只生成并持久化 `other` 回复，避免旧短链推演中模型同时代写双方造成的不真实。

### 需求

- 新增持久化分支会话、分支消息和分支回复任务模型。
- 创建 branch session 时保存目标消息、改写内容、cutoff-safe context pack 和会话级 memory pack。
- 后端 API 支持创建/读取 branch session、追加用户 `self` 消息、创建/查询回复任务。
- 同一 branch session 同一时间只保留一个 active reply job。
- 用户在 LLM 回复提交前继续追加 `self` 消息时，旧 job 必须被 supersede，旧 LLM 结果不能写入当前分支。
- worker 处理 branch reply job 时只能生成一条 `other` 消息，并在写入后更新 `current_branch_state`。
- 删除会话或重跑分析时必须清理相关 branch session/message/job 行。
- 旧 `/simulations` 入口保持兼容，不在本 PR 接入前端实时聊天。

### 验收标准

- 可以创建 branch session，并持久化初始 rewrite `self` 消息。
- 用户后续 `self` 消息可以追加，并递增 session `input_revision`。
- 创建新 reply job 时会 supersede 仍处于 queued/running 的旧 job。
- worker 使用最新 transcript 和会话 memory pack 生成回复，且只写入 `speaker_role=other` 的消息。
- LLM 返回后重新校验 job 状态与 `input_revision`，过期结果不会写入分支。
- 第二轮回复 prompt 包含完整 branch transcript。
- 删除 conversation 会清理 branch session、message 和 reply job。

## 工作记录及完成情况

- 已新增 `BranchSession`、`BranchMessage`、`BranchReplyJob` 三个 SQLAlchemy 模型，并在模型映射测试中覆盖新表注册。
- 已新增 `src/if_then_mvp/branch_sessions.py`，集中实现创建分支会话、追加 self 消息、创建 reply job、supersede active job、claim job 和 read-model 转换逻辑。
- 已新增 branch session/message/reply job 的 Pydantic schema，并在 FastAPI 中暴露 `POST /branch-sessions`、`GET /branch-sessions/{id}`、`POST /branch-sessions/{id}/messages`、`POST /branch-sessions/{id}/reply-jobs`、`GET /branch-sessions/{id}/reply-jobs`。
- 已在 `simulation.py` 新增 realtime branch reply prompt 和 `BranchReplyPayload`，明确 LLM 只回复 `other`，以 `persona_other` 为主约束，以 `persona_self` 辅助理解用户输入。
- 已在 `worker.py` 新增 `run_next_branch_reply_job()`，接入 worker loop；worker 在 LLM 返回后会回滚并刷新 session 状态，重新读取 job/session，基于 `input_revision` 丢弃 superseded 旧结果。
- 已更新 conversation lifecycle，在删除会话或重跑分析时清理 branch session、message 和 reply job，避免遗留旧分支状态。
- 已新增 `tests/test_branch_sessions.py`，覆盖创建、追加、队列 supersede、worker 只写入 other、过期结果丢弃、第二轮 transcript 和删除清理。
